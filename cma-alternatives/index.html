Alternatives to Claude Managed Agents

Infrastructure decision brief · v3 · full landscape

01 · Executive Summary

How to choose

Claude Managed Agents (CMA) is a hosted agent harness — sandboxing, sessions, memory, tool execution, and tracing, all run by Anthropic for $0.08/session-hour plus tokens. The alternatives split along two axes: who runs the infrastructure, and which models you can use. The right choice depends on lock-in tolerance, scale, and how much of the moat lives inside the agent's memory.

The decision in one sentence If your moat is memory and learning loops, own the harness. If your moat is the agent's task quality and you want to ship fast, let Anthropic run it.
MENTAL MODEL · THREE LAYERS

Most agent stacks have three distinct layers. Conflating them is how teams end up paying three vendors for one problem:

  • LOOP — the agent code itself: prompts, tools, control flow. Mastra · Vercel AI SDK · Claude Agent SDK · OpenAI Agents SDK · LangGraph · CrewAI
  • RUNTIME — durable execution: scheduling, retries, surviving disconnects. CMA · Cloudflare Agents · Inngest · Temporal · Trigger.dev · Vercel Workflows
  • SANDBOX — code execution isolation: where agent-written code actually runs. E2B · Modal · Daytona · Blaxel · Vercel Sandbox · Cloudflare Sandbox

Hosted platforms (CMA, Cloudflare Agents, Bedrock AgentCore) bundle all three. SDKs let you mix and match. Choose based on which layer you actually need to control.

The five buckets

A

Hosted, model-locked

CMA (Claude), Salesforce Agentforce (CRM-locked). Fastest to ship, deepest tuning, highest lock-in.

B

Hosted, model-agnostic

Cloudflare Agents (Think), Bedrock AgentCore, Microsoft Foundry, Google Vertex AI Agent Builder, OpenAI Agents SDK. Someone else runs the infra, models stay swappable. Cloudflare's hibernation pricing (free when idle) is the breakthrough.

C

SDK / library, you deploy

Claude Agent SDK, Mastra (TS), Vercel AI SDK, LangGraph, CrewAI, AutoGen. Full control over deployment. Engineering cost but no per-session platform fee. Mastra is the rising TypeScript-native option.

D

Self-hosted OSS

OpenClaw, Multica, Cabinet, Eigent. Maximum control, zero lock-in, full ops cost on your team.

E

Workflow / no-code

n8n, Dust, Relevance AI, Decagon. Visual builder, business-team-friendly, less custom logic but faster to deploy for standard workflows.

Three things people miss

i. Memory = lock-in

Models are easy to swap. Once agents have written months of memory into a proprietary store, switching costs explode.

ii. $0.08/hr scales

One agent for an hour is a rounding error. 500 agents running concurrently is $40/hr just for the harness, on top of tokens.

iii. Infra is consolidating

OpenAI, Anthropic, and Cloudflare are all bundling sandbox + memory + harness. Standalone primitives (E2B, Pinecone) are commoditizing fast.

02 · Recommendations for Ad Pros

Mapped to what you're actually building

Based on the current Ad Pros AI stack — Noor (ClickUp + BigQuery + Supabase + Claude API), the 8-agent Workflow Factory, the Media Intelligence Pipeline processing ~5K Meta ads/day, and the AI twin video pipeline — here's how the alternatives map to specific projects.

RECOMMENDED PRIMARY · NOOR / WORKFLOW FACTORY

Claude Agent SDK + your existing stack

Noor is already built on ClickUp, BigQuery, Supabase, and the Claude API. The Agent SDK formalizes what you have — agent loop, tool execution, context compaction — without forcing you onto Anthropic's hosted runtime. Keep Supabase as the memory store, BigQuery as the data layer, and skip session-hour fees on agents that run constantly.

Why

Your moat is the data layer + workflow logic, not the harness

Cost vs CMA

Save ~$60/mo per agent running 24/7 ($0.08 × 730 hr)

Risk

You own ops, but you're already running prod infra

USE FOR · MEDIA INTELLIGENCE PIPELINE

Stay on Anthropic Batch API

Don't move the ~5K ads/day pipeline to CMA. Batch API is 50% cheaper for high-volume async work, and you're not running a long-horizon agent — it's a stateless classification pipeline at scale. CMA's value is sessions and memory; you don't need either here.

Use CMA only for: the QA audit agent that reasons across full classification output.

WORTH PILOTING · CLIENT-FACING (FUTURE)

Claude Managed Agents

If Noor ever gets productized for clients (white-label agent infra for DTC brands), CMA's sandboxing, scoped permissions, and identity isolation are exactly what would otherwise take 3 months to build. Single-tenant per-client agents with session-hour pricing maps cleanly to client billing.

Why: multi-tenant security is the hardest part to build correctly.

STRONG CONTENDER · MULTI-AGENT WORKLOADS

Cloudflare Agents (Think)

The most interesting alternative for your stack. Each agent is a Durable Object with its own SQLite — millions of agents possible, free when idle (hibernation), pay only for CPU time when active. Model-agnostic via AI Gateway (14+ providers including Anthropic). Sandbox SDK + Dynamic Workers handle code execution. If you ever need 1 agent per client × 5 clients × 20 agents running mostly idle, this pricing model crushes CMA's session-hour fee.

Trade-off: TypeScript-first, requires Cloudflare Workers mental model. Best if a team member already knows the platform.

WATCH, DON'T ADOPT · MULTI-MODEL

Deep Agents Deploy (LangChain)

Useful insurance against Anthropic pricing or capability shifts, but not needed today — Claude is the default and it's working. Re-evaluate if a specific agent ever benefits from Gemini's long context or a local model for cost/privacy.

Trigger to revisit: Claude pricing increase, or vertical where Gemini's context window matters.

SKIP · NOT YOUR STACK

Bedrock AgentCore

Only makes sense if you were already on AWS. Adds vCPU-hour + GB-hour pricing complexity, AWS IAM overhead, and a second cloud to manage. You're on Supabase + Cloudflare R2 — staying there is correct.

SKIP · TEAM SIZE

Self-hosted OpenClaw / Multica

Right answer for a 200-person org with a platform team. At ~26 people with most engineering effort going into the products themselves, the ops burden of self-hosting an agent runtime is a tax you don't need to pay yet.

SUMMARY

Three patterns, not eight

Document the harness boundary clearly: which agents call CMA, which call the Agent SDK directly, which use Batch API. Three patterns is fine; eight is chaos.

SUGGESTED NEXT 30 DAYS
  1. 01. Audit current Noor agents → which actually need long-running sessions vs. one-shot calls? Most don't.
  2. 02. Pick one agent to pilot on CMA. The QA audit pipeline or a competitive intel deep-research agent are good candidates.
  3. 03. Keep Supabase as the source-of-truth memory store regardless of harness. Don't let agent memory get trapped in any vendor.
  4. 04. Document the harness boundary so the team knows when to reach for CMA vs. SDK vs. Batch API.

05 · Decision Questions

42 questions, 8 categories

Work through these in order. Categories A–C eliminate most options; D–H refine the choice. Each question includes the reasoning behind why it matters.

CATEGORY A
Workload fit
Before anything else, figure out if you even need an agent harness. Most so-called 'agents' are actually workflows or one-shot LLM calls dressed up.
01

Does this agent actually need a long-running session?

If the work is one-shot or batch-classifiable, you don't need an agent harness — use Messages API or Batch API. Agent harnesses shine for tasks that run minutes to hours with stateful memory.

→ CMA, Cloudflare, and Bedrock all charge for the harness. Pay only when you need it.
02

Is the task synchronous or async?

Sync (user is waiting): hosted is fine, latency matters less. Async (background, hours-long): hibernation pricing (Cloudflare) or session-hour pricing (CMA) matters a lot.

→ Long async work is exactly where Cloudflare's free-when-idle model dominates.
03

How does the agent receive input — chat, webhook, schedule, event?

Chat: any platform works. Cron/scheduled: Cloudflare's built-in scheduler is best. Event-driven (Slack, email, webhooks): all platforms support it but Cloudflare is most native.

→ If you're already running cron jobs in n8n or Supabase, that's a sign the harness should support scheduling.
04

What's the expected concurrency at peak?

1–10: hosted is fine. 50+: model the harness fee carefully. 1000+ (one per user/client): only Cloudflare's hibernation model handles this economically.

→ At 100+ idle agents, CMA costs ~$240/mo just for the harness. Cloudflare costs ~$15.
05

Will the agent need to coordinate with other agents (multi-agent)?

Single agent: anything works. Multi-agent: CMA has it in research preview, Cloudflare has sub-agents shipping, LangGraph has it as a primitive.

→ Don't bet on research-preview features for production roadmaps.
CATEGORY B
Memory & state
Where memory lives is where lock-in lives. This category determines how reversible your decision is.
06

Where does the agent's memory live, and who owns it?

Memory in vendor stores (CMA's Memory beta, Bedrock Memory) creates real lock-in. Memory in your own database (Supabase, Postgres) is portable. Memory in Durable Objects (Cloudflare) is somewhere between — yours but tied to Cloudflare's runtime.

→ Rule: never put memory you can't export into a proprietary store.
07

Does memory need to be shared across agents or per-agent?

Per-agent: any platform. Shared workspace memory: CMA Memory, Cloudflare Vectorize + R2, or your own Supabase. Cross-tenant shared: build it yourself.

→ Cloudflare's per-Durable-Object SQLite is naturally per-agent. Sharing requires Vectorize or D1.
08

Do you need cross-session memory persistence?

Most teams say yes, then realize their agents don't actually need it. If the agent is one-shot or stateless within a task, skip memory entirely.

→ Memory is the second-most over-engineered thing in agent stacks (after multi-agent orchestration).
09

Do you need vector / semantic search?

If yes: Cloudflare has Vectorize built in, CMA doesn't (you'd add Pinecone/Supabase pgvector), Bedrock has Knowledge Bases. Plan this upfront.

→ Vectorize being in the same platform is a real Cloudflare advantage for RAG-heavy agents.
10

How will you audit / replay agent decisions?

Memory + tracing together. CMA Console gives this for free. Cloudflare gives logs + AI Gateway. LangSmith does this on top of LangGraph. Self-hosted means building it.

→ Without replay, debugging production agents is impossible.
CATEGORY C
Models & lock-in
Models are easy to swap. Harnesses, memory, and tool integrations are the actual switching cost.
11

Are you committed to one model family, or do you need flexibility?

If only Claude: CMA + Agent SDK are fine. If you want any of GPT, Gemini, Llama, or local: choose Cloudflare (14+ providers via AI Gateway), Deep Agents, or LangGraph.

→ Multi-model isn't theoretical — Gemini's long context, GPT-5's reasoning, and local privacy are real use cases.
12

Do you need to A/B test models across the same agent task?

Cloudflare AI Gateway has this natively (one-line model swap). LangSmith has it via tracing. CMA doesn't really.

→ If model performance matters to your business case, you'll want this.
13

What's your fallback plan if the primary model goes down?

Cloudflare AI Gateway has automatic fallback. CMA doesn't. Self-built: you wire it yourself.

→ Anthropic has had outages. So has every other provider.
14

How locked-in are you willing to be on the harness?

High lock-in (CMA): fastest to ship, hardest to leave. Low lock-in (Cloudflare, OSS): more setup, easier to leave. Decide explicitly.

→ Lock-in cost = (engineering days to migrate) × (probability you'll need to migrate).
15

Can you export your agent definitions and memory?

If you can't export to JSON/markdown, treat that as a red flag. CMA exports memory as files. Cloudflare's DO state is queryable. Bedrock's is more opaque.

→ Export-ability is the cheapest insurance policy.
CATEGORY D
Cost & scale
Three different pricing models — session-hour, CPU-time, and your own infra. Each wins at different scales.
16

What's your peak concurrent agent count?

1–10 active concurrently: any platform fine. 50–500: pricing model matters. 500+: Cloudflare's hibernation model is structurally cheapest.

→ Model 12-month worst-case before committing.
17

What's the active vs. idle ratio?

Mostly active (8 hr/day): CMA, SDK, Bedrock all comparable. Mostly idle (1 hr/day): Cloudflare wins by 10×.

→ Calculate this honestly. Most agents are idle 95% of the time.
18

Are you scaling linearly with clients, users, or tasks?

Linear with clients: per-tenant pricing matters (CMA's session billing, Cloudflare's per-DO pricing). Linear with tasks: token cost dominates, harness is rounding error.

→ If 1 client = 10 agents, you'll want a pricing model that doesn't punish you for adding clients.
19

Is the cost passable to clients?

CMA's $0.08/session-hour is a clean line item to bill clients. Cloudflare's CPU-time pricing is harder to translate. Self-hosted is opaque.

→ Performance pricing models like yours benefit from billable line items.
20

What's the infrastructure cost beyond tokens?

Tokens are equal across platforms. Harness premium ranges from $0/mo (SDK self-deploy) to ~$700+/mo (CMA at scale) for the same workload.

→ Total cost = tokens + harness + ops time. Don't ignore the third.
CATEGORY E
Security & multi-tenancy
If clients ever touch your agents, this category becomes the most expensive part of the build.
21

Will agents touch client data, or only internal data?

Internal only: any platform. Client data: hosted (CMA, Cloudflare, Bedrock) saves 2–3 months of security work.

→ Multi-tenant security is the single most underestimated cost in agent infra.
22

Do you need per-client tenant isolation?

CMA does this with scoped permissions + identity. Cloudflare does this naturally (one Durable Object per client). Self-hosted: you build it.

→ If you ever productize this, isolation must be airtight on day 1.
23

What's the secrets/credentials story?

CMA has built-in credential management (creds never reach the sandbox). Cloudflare has Workers Secrets + Outbound Workers. Self-hosted: Vault or roll-your-own.

→ Leaked credentials in an agent prompt is a top-3 incident pattern.
24

Does the agent need network access, and if so, where?

All hosted platforms support allowlist-style network rules. Cloudflare's Outbound Workers + Mesh are most granular.

→ Default-deny network access is the right starting posture.
25

What's the data residency requirement?

If client contracts require EU/specific-region data: only self-hosted or AWS Bedrock (with region pinning) work cleanly. CMA and Cloudflare are global by default.

→ Most DTC ecommerce contracts don't require this. Enterprise clients sometimes do.
26

What happens if a prompt injection succeeds?

Sandboxing limits blast radius. CMA, Cloudflare, and Bedrock all sandbox. Self-deployed Agent SDK requires you to sandbox yourself.

→ Assume prompt injection will happen. Design for it.
CATEGORY F
Team & operations
The platform that fits your team's skills and ops capacity will win, regardless of theoretical merit.
27

Who runs this in production at 2am?

Hosted (CMA, Cloudflare, Bedrock): vendor on-call handles infra. Self-hosted: it's your team.

→ Factor incident response cost. One bad weekend > a year of hosted fees.
28

Does your team know TypeScript or Python better?

Cloudflare is TypeScript-native. CMA + Agent SDK have Python and TypeScript. CrewAI/LangGraph are Python-first.

→ Don't fight your team's existing stack.
29

How fast does this need to ship?

CMA: days. Agent SDK + Supabase: weeks. Cloudflare Agents: weeks (faster if team knows Workers). Self-hosted OSS: months.

→ Fastest path to production-ready almost always wins for first iteration.
30

Who maintains this 12 months from now?

If it's a single dev's pet project, maintainability is a real risk. Hosted platforms reduce maintenance burden. OSS platforms put it on your team.

→ Bus factor of 1 is a critical risk for production agents.
31

How will you measure agent quality?

CMA Console: free tracing. Cloudflare AI Gateway: per-call observability. LangSmith: built for this. Self-hosted: you build evals.

→ Eval velocity is often the real bottleneck, not infra.
32

How will you ship breaking changes safely?

All platforms support versioning agents. CMA has agent IDs. Cloudflare has Workers versioning. Plan a staging environment from day 1.

→ Production agents that update without canary testing will eventually break a client.
CATEGORY G
Migration & reversibility
If you're wrong, how hard is it to switch? Bias toward decisions that are reversible in weeks, not quarters.
33

What's the migration path off this platform?

CMA → Agent SDK: 2–4 weeks. CMA → Cloudflare: 5–8 weeks. Cloudflare → CMA: 4–7 weeks. Plan the exit before you commit.

→ Migration cost > expected migration probability × migration cost. If switching is easy, lock-in matters less.
34

Are agent definitions portable?

If you write agents in your own markdown/YAML spec and translate to the platform's API, switching costs drop dramatically. If you write directly against the platform's API, you're locked in.

→ 1 week of upfront abstraction work saves 6 weeks of migration later.
35

Are tool integrations portable?

MCP-based tools port cleanly across all platforms (CMA, Cloudflare, Agent SDK all support MCP). Custom tools written against a specific platform's API don't.

→ Default to MCP for tool definitions when possible.
36

Can you run two platforms in parallel during transition?

Yes for everything. The friction is shared memory + shared tooling. Plan a 2–4 week parallel-run window for any major migration.

→ Parallel running de-risks the cutover.
37

What's your fallback if the vendor pivots, raises prices, or shuts down?

Hosted platforms can change pricing or sunset features unilaterally. OSS platforms can't. Hybrid (Cloudflare + own DB) is a reasonable middle.

→ Ask: 'If this vendor 5x'd prices tomorrow, what would I do?' If the answer is 'panic,' rethink.
CATEGORY H
Strategic fit
Beyond the technical questions, does this decision serve where the business is going?
38

Does this fit the existing stack?

Ad Pros runs Supabase + ClickUp + BigQuery + Cloudflare R2. Cloudflare Agents fits naturally (R2 already there). CMA + Supabase memory fits. Bedrock requires a second cloud.

→ Stack coherence reduces ops surface area.
39

Will this support productization to clients later?

If Noor gets white-labeled for clients, multi-tenancy + per-client billing matter. CMA's session-hour pricing is billable. Cloudflare's per-DO scaling is billable. Self-hosted requires building this.

→ Build for the product you'll have in 18 months, not just today.
40

Does the platform's roadmap align with where you're going?

CMA roadmap: deeper Claude integration, multi-agent, dreaming. Cloudflare roadmap: agents-as-customers, durable execution at scale. Both align with autonomous agents.

→ Vendor roadmap = where you'll be locked in next year.
41

Are you optimizing the right thing?

Most teams overweight infra choice and underweight prompt quality, tool design, and data plumbing. The harness rarely determines whether the agent works.

→ Spend 20% of your time on infra, 80% on prompts/tools/evals.
42

What's the single biggest risk you're not pricing in?

For Ad Pros: probably memory lock-in if you bet on CMA Memory before it's GA. Or under-investing in evals. Or ops debt from running Cloudflare without TypeScript depth on the team.

→ Name the biggest risk explicitly. Then mitigate it before it bites.

REVERSIBILITY PRINCIPLES
  1. Keep memory in your own database (Supabase) regardless of harness — never in vendor stores
  2. Wrap MCP tool calls in your own interface so swapping harness doesn't touch tool code
  3. Standardize agent definitions in markdown/YAML you control, not vendor APIs
  4. Run evals against agent outputs, not harness internals — outputs port across platforms
  5. Pilot any new harness on one non-critical agent for 30 days before broader adoption
THE CHEAP INSURANCE

Even if committed to CMA today, do these three things to keep the door open:

  • Mirror agent memory writes to Supabase as the source of truth
  • Define agents in your own markdown/JSON spec, then translate to CMA API on deploy
  • Keep a working Claude Agent SDK fallback for at least one critical agent

~1 week of upfront work. Saves 6-10 weeks if you ever need to switch.
