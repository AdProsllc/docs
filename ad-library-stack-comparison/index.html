02 THE PROBLEM & SCALE

What we're collecting, and why the unit model matters

Target: 5,000 brands × ~200 ads each = ~1M ads/month of Ad Library metadata (creative text, ad_archive_id, start dates, page identity, delivery surface). First month is a full backfill; after that, deduping on ad_archive_id means we only pay to collect new ads — most brands add 20–50/month, dropping steady-state volume to ~150–250K ads/month. Every stack below benefits from this, but it hits per-ad-priced vendors hardest.

The single most important pricing insight: vendors bill on different units. Some charge per ad (Apify actors, Bright Data records). Some charge per request, where one request returns a full page of ~30–50 ads (ScrapeCreators). Some are fixed-cost infrastructure (self-hosted Playwright: VPS + proxy bandwidth, volume nearly free). Per-request and fixed-cost models get 1–2 orders of magnitude cheaper at our volume.

Per-ad billing

Cost scales linearly with volume. 1M ads at $0.20–0.75/1K = $200–750 before platform fees. Delta-scraping helps, but plan floors remain.

Per-request billing

~35 ads arrive per request, so 1M ads ≈ 33K requests. At ~$1/1K requests, the whole backfill is ~$33. The unit does the work.

Fixed-cost infra

A $15 VPS + $15–40 of proxy bandwidth collects everything. Marginal cost per additional brand approaches zero — the resale story.

04 STACK PROFILES

Seven stacks, pros and cons

A

Apify cheapest actor → BigQuery current stack

Managed actor at ~$0.20/1K ads, plus the Apify plan (~$40/mo), compute units, and residential proxy bandwidth. This is what we run today.

Backfill $315–415 · steady-state $105–145/mo · $0.32–0.42 per 1K ads

Pros
  • Zero engineering or maintenance
  • Many competing actors — easy to switch within the platform
  • Already integrated into our pipeline
Cons
  • 5–7× more expensive all-in than the best alternatives
  • Per-ad billing + plan floor + proxy overage surprises
  • Actor reliability varies; cheapest actors have the least support
  • Plan floor dominates steady-state cost even after delta cuts volume
B

ScrapeCreators → BigQuery quick win

Unofficial Ad Library API billed per request (~35 ads/page). Credits never expire, no monthly minimum, no rate limits, unlimited concurrency. ~33K requests covers the full 1M-ad backfill.

Backfill $55–60 · steady-state $30–35/mo · $0.055 per 1K ads

Pros
  • Cheapest managed option by a wide margin — per-request unit model
  • Half a day to swap the collector; everything downstream unchanged
  • No plan floor; credits never expire; unlimited concurrency for fast sweeps
  • Returns raw Meta GraphQL JSON with ad_archive_id — clean dedupe
Cons
  • Solo-founder operation — key-person and continuity risk
  • Ads-per-page unmeasured; thin pages (10–15 ads) would 2–3× the cost (still far under Apify)
  • Unofficial API — same ToS gray zone as all scraping vendors

Open action: negotiate per-ad or custom volume pricing with the founder — locks predictability and removes the ads-per-page risk entirely.

C

Self-hosted Playwright (GraphQL interception) → BigQuery

Playwright captures the Ad Library's own GraphQL responses (no HTML parsing, no login required), blocks all media requests to cut proxy bandwidth ~90%, and amortizes sessions across many brands. ScrapeGraphAI open-source + Claude acts as a self-healing repair layer when Meta changes schema.

Backfill $55–85 · steady-state $50–70/mo · $0.06–0.09 per 1K ads

Pros
  • We own the pipe — no vendor margin, no key-person risk, strategic asset for resale products
  • Marginal cost per additional brand approaches zero
  • Media-blocking makes residential proxy cost trivial ($15–40/mo)
  • AI-maintenance turns the classic self-host killer (parser upkeep) into ~$5/mo of tokens — our structural advantage as an AI-native agency
Cons
  • 1–2 weeks of build + ongoing ownership
  • Blocks and breakage risk when Meta changes anti-bot posture
  • Fixed costs don't shrink with delta volume
  • We carry the scraping posture directly rather than through a vendor
D

Hybrid: Playwright primary + ScrapeCreators failover recommended

Stack C carries the volume; routing logic falls back to Stack B automatically for brands that fail or when our IPs draw heat. Two independent collection paths, one pipeline.

Backfill $65–100 · steady-state $60–85/mo · $0.07–0.10 per 1K ads

Pros
  • Lowest overall risk — no single point of failure, vendor or infra
  • Cost within noise of the cheapest single option
  • Owns the infrastructure layer the resale business sits on
  • Failover doubles as a benchmark: continuous data-quality comparison between paths
Cons
  • Same 1–2 week build as Stack C plus routing logic
  • Two systems to monitor instead of one
E

Hosted ScrapeGraphAI (AI extraction) → BigQuery

AI-powered extraction API: ~10 credits per Ad Library page (Extract 5 + stealth 5). Powerful for unstructured sites — but the Ad Library already serves structured GraphQL JSON, so we'd be paying an LLM to re-derive structure that exists.

Backfill $450–550 · steady-state $120–180/mo · $0.45–0.55 per 1K ads

Pros
  • Zero maintenance, auto-adapts to page changes
  • Open-source library is free — ideal as Stack C/D's self-heal repair kit
  • Stealth mode is a good break-glass fallback when our IPs are hot
  • n8n + MCP integrations slot into our existing orchestration
Cons
  • Wrong unit economics for structured, high-volume data — ~10× ScrapeCreators
  • AI extraction adds latency and a per-page LLM cost we don't need
F

Bright Data pre-collected dataset → BigQuery

Buy the data instead of scraping it: ~$250/100K records list price, monthly-refresh subscriptions discounted up to ~80%, "smart updates" bill only changed records, native delivery to Google Cloud. Legally the cleanest posture (favorable US ruling on scraping public data).

Backfill $500–2,500 (negotiated tier) · steady-state $150–500/mo · $0.50–2.50 per 1K ads

Pros
  • Zero engineering, zero scraping risk, enterprise SLA
  • Smart updates = delta-scraping as a product
  • Cleanest legal posture of any option
  • Native BigQuery delivery
Cons
  • 5–10× the cost of B/C/D at every stage
  • Coverage and freshness on our exact 5,000-brand list needs verification
  • Dependency on their collection scope decisions
G

Free official EU API + paid collection for the US-only tail

Since the DSA, Meta's official Ad Library API returns all ads (not just political) for any ad that delivered in the EU — free, ~200 calls/hour per app, roughly 1–2 calls per brand. Route EU-delivering brands through the API at $0; use Stack B or C only for US-only brands.

Backfill $45–75 · steady-state $25–50/mo · $0.05–0.08 per 1K ads (at ~40% EU coverage)

Pros
  • Cheapest possible blend; official-API data includes EU reach data no scraper gets
  • Fully sanctioned collection path for the covered segment
  • Rate limits are a non-issue at our call volume
Cons
  • Coverage split: US-only DTC brands don't appear — needs a per-brand routing layer
  • Requires ID-verified developer app(s)
  • Two schemas to normalize into one table
